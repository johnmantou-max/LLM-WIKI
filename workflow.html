可執行的工作流程

流程不是一句「幫我檢查」。每一個節點都有輸入、輸出、可驗證的條件，以及失敗時的退回路線。

01 / INTAKE

來源受理

本次依使用者選定的五篇網址製作來源摘記；往後仍須使用者指定

02 / EXTRACT

解析與定位

保留 SHA-256、PDF 頁碼、每頁行號

03 / EVIDENCE

來源證據卡

整理直接證據、矛盾、適用條件

04 / SYNTHESIZE

撰寫知識

依六領域整合成 Markdown Wiki

05 / LINT

品質檢查

檢查引用、結構、缺漏和連結

06 / HUMAN

人工確認

檢查語義忠實度，核准文章與大綱

07 / RENDER

產生網頁

正式版僅使用已核准文章；未核准稿僅可做清楚標記的預覽

08 / VERIFY

渲染驗收

瀏覽器檢查溢出與連結

09 / DELIVER

交件與反思

附過程、限制、檢查報告及網站網址

Loop 剎車條件每個節點最多修正 3 輪；全部通過就停止。缺來源、來源不支援結論、資料矛盾未釐清或達到上限時停止並記錄，不得編造答案。

失敗時退回哪裡？

引文位置錯誤 → EVIDENCE / EXTRACT

核對原始文字、修正位置，不必重建全部頁面。

教學內容不符來源 → SYNTHESIZE

只修改錯誤 Wiki 文章，再重新產生對應頁。

文字溢出 → RENDER

只修 CSS 與排版，不在排版時變更原始論點。
